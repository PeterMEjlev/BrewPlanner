# Remaining Codebase Cleanup and Consolidation Plan

Updated: 2026-08-31

This document contains only cleanup work that remains after the first implementation pass. Completed entries have been removed rather than retained as a historical checklist. Git history records the completed work.

# 1. Executive Summary

The codebase is in good condition after the first cleanup pass. Type checking, strict unused-local/parameter checks, all workspace tests, and all production builds pass. Static analysis no longer finds an unused source file.

The best remaining consolidation opportunities are:

1. Share fermenter-status history polling between Dashboard and KioskHome while preserving their styling and Dashboard's cross-remount cache.
2. Extract the common Google service-account JWT/token implementation used by Drive and FCM.
3. Extract the common lifecycle used by the five Python sensor agents without erasing their hardware-specific behavior.
4. Centralize update-status wire contracts and status-file/log reading while leaving local and remote update triggers separate.
5. Decompose Dashboard and Settings along stable feature boundaries after their shared logic has moved out.

The remaining confirmed deletions are mostly binary artifacts and unused public/type surface. The checked-in recipe backups, legacy environment alias, CommonJS aliases, and any shared exports potentially consumed by an external brew-system repository still require external verification.

No direct dependency is proven unused. Dependency work should therefore focus on classification and controlled parent-package upgrades, not speculative removal.

# 5. Duplicate and Redundant Code

## 5.1 Fermenter-status polling

**Locations:** `apps/web/src/pages/Dashboard.tsx` and `KioskHome.tsx`.

Both independently locate a gravity device, fetch recent gravity history, poll once per minute, derive online/fermenting/complete state, and retain the last verdict through transient failures. Dashboard additionally keeps a cross-remount cache and returns a page-specific shell class; Kiosk uses different color classes.

Create `apps/web/src/hooks/useFermentStatus.ts` that returns semantic state (`offline`, `online`, `fermenting`, `complete`) and any needed metadata. Preserve Dashboard's cache behavior explicitly. Let each page continue mapping state to its own classes. Remove both local hooks afterward. Add fake-timer/history tests for every state, remount behavior, failures, and device changes. Risk: **Medium**.

## 5.2 Google service-account authentication

**Locations:** `apps/server/src/googleDrive.ts` and `apps/server/src/notify/push.ts`.

Both parse service-account JSON, base64url-encode JWT parts, sign an RSA assertion, exchange it at Google's OAuth endpoint, cache the token, and refresh before expiry. Drive additionally supports refresh-token OAuth; FCM requires `project_id`; their environment variables and failure policies differ.

Extract a server-internal `googleAuth.ts` that validates service-account credentials and mints/caches a token keyed by credentials and scope. Keep Drive refresh-token support, FCM project selection, optional-feature behavior, logging, and endpoint-specific errors in their callers. Risk: **High**.

## 5.3 Sensor-agent lifecycle

**Locations:** all `deploy/agents/*/agent.py` files.

All five repeat timestamping, logging, MAC lookup, authenticated posting, server-provided interval updates, buffered retry, next wall-clock slot calculation, interruptible sleep, signal shutdown, and main-loop scaffolding. Power, water, and pressure are closest; Tilt and Inkbird have distinct scanning/command concerns.

Extract `deploy/agents/common.py` or a small deployable package containing lifecycle/network/scheduling primitives with callback-based sensor reads. Keep hardware imports and acquisition local; keep Inkbird command handling separate. Update every copy/install/service path to deploy the shared module. Risk: **High**.

## 5.4 Local and remote update status handling

**Locations:** `apps/server/src/system/update.ts`, `system/brewSystemUpdate.ts`, and duplicated web response interfaces.

The server modules repeat status shapes, status-file parsing, and log-tail assembly. Their triggers must remain separate: local update hands off to systemd; remote rig update has detached execution, safety preflight, and stale-state detection.

Move wire response types into `@checklist/shared`. Extract only a server-internal status-file/log utility parameterized by paths and state validation. Keep both trigger workflows and safety rules in their existing modules. Risk: **Medium**.

## 5.5 Password-visibility icons

**Locations:** `apps/web/src/pages/Login.tsx` and `SettingsDesktop.tsx`.

The local Eye/EyeOff SVG components are duplicated. Move them into `components/icons.tsx` only if their view boxes, accessibility behavior, and styling inputs remain identical. This is low-value and should follow the domain consolidations. Risk: **Low**.

# 6. Consolidation Opportunities

## 6.1 Decompose the largest orchestration pages along feature boundaries

`Dashboard.tsx` and `SettingsDesktop.tsx` still combine several independent panels, API effects, helpers, and dialog states. Extract stable domains rather than tiny visual fragments:

- Dashboard: `FermenterCommandCenter`, brewery utility cards, `KegInventoryPanel`, `BrewSystemCard`, `KegFridgeCard`, and pure metric formatters. Keep route-level coordination and responsive layout in `DashboardPage`.
- Settings: Display, Bruce, Sensors, Brewing, Notifications, Accounts, Updates, and Reset sections, plus local `Card`, `Row`, and segmented-control primitives only where markup and behavior are genuinely identical.

Move one panel per commit without changing requests, polling cadence, state ownership, labels, or CSS classes. `Bruce.tsx` and `RecipeEditor.tsx` are also large but more cohesive; split only state/API-isolated panels or reusable editor primitives. Risk: **Medium**.

## 6.2 Keep shared contracts centralized without creating a dumping ground

Continue using `@checklist/shared` for cross-boundary wire types, constants, and pure brewing math. Keep React helpers, repositories, environment access, HTTP calls, and user-facing error prose in their owning application.

The shared package may be split into internal topic files as real boundaries emerge, while retaining its public barrel. Do not perform a mechanical line-count split.

## 6.3 Add a reviewed unused-code check

Add a `check:unused` command or CI step after the remaining public surface is cleaned. Configure explicit entries for server CLIs/scripts, web entry points, Bruce CommonJS registration, Android conventions, and deployment scripts. Static output must remain reviewed rather than becoming an automatic deletion list.

## 6.4 Avoid low-value abstractions

Leave these separate unless future behavior converges:

- Mobile versus desktop keg cards.
- Local versus remote update triggers.
- Server device repository versus fallback facade.
- Bruce chat versus voice passage rendering where response context differs.
- Tiny time/error/mapping helpers that belong to their feature.
- LocalStorage settings versus server-backed preferences.
